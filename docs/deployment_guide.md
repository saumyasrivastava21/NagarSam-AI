# NagarSam AI — Production Deployment Guide

This guide documents the production deployment architecture, configuration, infrastructure provisioning, and monitoring for NagarSam AI across AWS and containerized environments.

---

## 1. High-Level Production Architecture

```
[ Citizen / Officer / Worker / Admin ]
                 │
                 ▼
       [ CloudFront / Vercel ]
                 │

   [ AWS Application Load Balancer / NGINX ]
                 │
       ┌─────────┴─────────┐
       ▼                   ▼
[ FastAPI App Container ] [ FastAPI Worker ]

       ▼

       │
       ▼

```

## 2. Infrastructure Components

### A. Database: PostgreSQL 15+ with PostGIS
- **Managed Service**: AWS RDS PostgreSQL 15+ or Aurora Serverless v2 PostgreSQL.
- **Extensions**:
  ```sql
  CREATE EXTENSION IF NOT EXISTS postgis;
  CREATE EXTENSION IF NOT EXISTS postgis_topology;
  ```
- **Connection String**: `postgresql+psycopg://<user>:<password>@<rds-endpoint>:5432/<dbname>`
- **Migrations**: Executed on deploy via `alembic upgrade head`.

### B. Object Storage: Amazon S3
- **Bucket Configuration**: Private bucket (`nagarsam-ai-storage-prod`) with SSE-S3 encryption enabled.
- **Access Control**: IAM Role with least-privilege `s3:PutObject`, `s3:GetObject`, `s3:DeleteObject`.
- **Signed URLs**: Uploads and downloads access files via short-lived Presigned URLs (default TTL: 3600 seconds).

### C. Caching & Asynchronous Queue: Redis 7
- **Managed Service**: AWS ElastiCache for Redis or standalone Redis container.
- **Purposes**: Celery async job broker, session cache, geospatial query cache.

### D. Application Compute: Amazon ECS with AWS Fargate
- **Container Registry**: Amazon ECR (`<account-id>.dkr.ecr.<region>.amazonaws.com/nagarsam-backend`).
- **Healthcheck Probe**: `GET /api/v1/system/health` returning HTTP 200 with DB, Redis, and Model readiness.
- **CPU/Memory Specs**: 2 vCPU, 4GB RAM per task (CPU inference) or GPU-enabled G4dn instances for high-throughput batch inference.

### E. Frontend Hosting: Vercel / CloudFront + S3
- **Build Output**: `dist/` generated by `npm run build`.
- **Environment**: `VITE_API_BASE_URL=https://api.nagarsam.ai/api/v1`, `VITE_API_MODE=production`.

## 3. Environment Configuration (`.env`)

| Variable | Description | Example / Default |
|---|---|---|
| `DATABASE_URL` | PostgreSQL + PostGIS Connection URL | `postgresql+psycopg://user:pass@host:5432/nagarsam` |
| `USE_POSTGIS` | Enable native PostGIS geometry | `true` |
| `REDIS_URL` | Redis connection URL | `redis://localhost:6379/0` |
| `JWT_SECRET_KEY` | High-entropy secret key for JWT signing | 64-char random hex string |
| `JWT_ACCESS_TOKEN_EXPIRE_MINUTES` | Access token lifespan | `1440` (24h) |
| `JWT_REFRESH_TOKEN_EXPIRE_DAYS` | Refresh token lifespan | `7` |
| `OBJECT_STORAGE_PROVIDER` | Storage backend (`local` or `s3`) | `s3` |
| `S3_BUCKET_NAME` | S3 bucket name | `nagarsam-prod-media` |
| `AWS_REGION` | AWS Region for S3 and KMS | `ap-south-1` |
| `POTHOLE_MODEL_PATH` | Path to YOLO pothole model checkpoint | `./models/pothole_best.pt` |
| `GENERAL_MODEL_PATH` | Path to YOLO road defect model checkpoint | `./models/nagrik OS initial.pt` |
| `MODEL_DEVICE` | Compute device (`cpu` or `cuda`) | `cpu` |
| `CORS_ALLOWED_ORIGINS` | Comma-separated CORS allowed origins | `https://nagarsam.ai,https://admin.nagarsam.ai` |

## 4. Local Deployment with Docker Compose

Run the entire platform locally with a single command:

```bash
docker-compose up --build -d
```

Verify service statuses:
```bash
docker-compose ps
```

Check health:
- Backend Health: `curl http://localhost:8000/api/v1/system/health`
- Frontend UI: Open `http://localhost:3000`

## 5. Continuous Integration & Quality Gates

All pull requests and commits to `main` trigger `.github/workflows/ci.yml`:
1. **Backend Test Suite**: Python 3.11, pytest, database integration, E2E lifecycle test.
2. **Frontend Test Suite**: Node.js 22, TypeScript check (`tsc --noEmit`), Vitest suite, Vite production build.
